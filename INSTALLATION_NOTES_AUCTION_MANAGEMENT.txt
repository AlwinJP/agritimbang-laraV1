AGRITIMBANG - AUCTION SCHEDULE & FARMER LIVESTOCK REGISTRATION UPDATE
Incremental overlay: schedule conflict prevention, automatic lifecycle, details view, and relationship repair.

CHANGES IN THIS UPDATE
1. Prevents overlapping auction schedules at the same Auction House on the same date. The check covers Draft, Published, Ongoing, and Completed schedules; Cancelled schedules release the time slot. Adjacent events are allowed when one ends exactly as the next begins.
2. Venue row locking serializes schedule creation/update requests so simultaneous submissions cannot reserve overlapping time slots.
3. Expected End Time is now required for newly created schedules and must be later than Start Time on the same date.
4. Published schedules automatically become Ongoing at the scheduled start date/time.
5. Ongoing schedules automatically become Completed at the expected end date/time. Legacy schedules without an expected end time fall back to 11:59:59 PM on the auction date.
6. Automatic completion updates still-registered livestock registrations to Completed and releases the active livestock registration key.
7. Encoders can no longer manually mark schedules Ongoing or Completed. The only manual lifecycle actions are Publish and Cancel.
8. Added a View Details action showing the schedule creator, created/updated timestamps, venue, municipality, barangay, registration window, publication time, description, and registrations.
9. Removed the requested explanatory/helper text and the Initial Status selector from the schedule form.
10. The schedule form now has Cancel, Save as Draft, and Publish Schedule buttons. Publishing a draft triggers farmer notifications.
11. Added missing `latestWeightEstimation()` and `latestValuation()` relationships to LivestockRecord. This fixes the undefined relationship error affecting Farmer Auctions and Livestock Directory eager loading.
12. Strengthened the Farmer schedule-card click handler so View Schedule opens the selected schedule and reports API errors in the page alert.

AUTOMATIC STATUS SCHEDULER
A new Artisan command is included:
- `php artisan auctions:sync-statuses`

It is scheduled every minute in `routes/console.php`. For continuous automatic status updates in a deployed environment, Laravel's scheduler must be running (the server's Laravel scheduler/cron, or `php artisan schedule:work` during local development). Schedule index/detail and registration requests also synchronize status as a fallback when a page/API request occurs.

AUCTION HOUSE OVERLAP RULE
Two schedules at the same Auction House cannot overlap on the same auction date. Example: 8:00 AM–11:00 AM conflicts with 10:30 AM–12:00 PM. 8:00 AM–11:00 AM followed by 11:00 AM–1:00 PM is allowed. Cancelled schedules do not block a new schedule. Drafts reserve their time slot to prevent two Encoders from preparing conflicting events.

INSTALLATION
1. Back up the project and database.
2. Extract this ZIP into the Laravel project root and merge/overwrite the included files.
3. No new database migration is included in this update. The original Auction Management migrations still need to have been run once.
4. Run:

   php artisan optimize:clear
   php artisan auctions:sync-statuses
   npm run build

5. For automatic transitions without relying on page visits, ensure Laravel's scheduler is running. In local development, run `php artisan schedule:work` in a separate terminal.

NOTES
- The previous Auction Management migrations (`auction_schedules` and `auction_registrations`) remain required if they have not already been applied.
- Existing schedule rows with a null expected end time are treated as ending at 11:59:59 PM on the auction date. New schedules require an expected end time.
- Existing livestock, transaction, valuation, and auction registration records are preserved.
- The missing Eloquent relationships are model-level fixes; no migration is needed for them.
